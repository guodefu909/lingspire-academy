# 决策日志

记录技术决策及其理由。

> ADR（架构决策记录）捕获实现过程中做出的重要技术或架构选择。

> 格式：`D001: 猫头鹰伙伴设计决策 (2026-07-11)`

记录原则：

- 推荐使用 `npx lee-spec-kit decision add <功能引用> --title "..." --context "..." --decision "..." --rationale "..." --evidence "..."` 创建新 ADR。
- 每个 ADR 必须同时记录**决策（选择了什么）**和**追溯（如何评估和验证的）**。
- 每个 ADR 必须包含至少一个**证据链接**（提交、PR 或测试/日志证据）。

## D001: 猫头鹰伙伴设计决策 (2026-07-11)

- **背景**：问题情境或背景
- **约束**：约束条件（时间/技术/运维/兼容性）
- **备选方案**：考虑过的替代方案
- **决策**：最终选择
- **理由**：选择的原因
- **追溯**：
  - **DOING 开始时**：初始推理/假设
  - **DONE 之前**：选定方案的最终推理
  - **合并后检查**：观察到的实际结果/影响
- **证据**：
  - **提交**：提交哈希或链接
  - **PR**：PR 链接
  - **测试/日志**：测试输出/日志/截图路径
- **后果**：结果和影响（可选）
